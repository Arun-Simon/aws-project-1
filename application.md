# ElderPinq Application Overview

This document explains what the ElderPinq application is, how it is built, and what each microservice does.

## What is ElderPinq?
ElderPinq is an elderly care support application built as a microservices demo. It combines a single-page React UI with several Node.js backend services and PostgreSQL databases, organized so each bounded domain has its own service and data store.

The application is intended to:
- provide secure authentication for elder users and family members
- record health check-ins and vital signs
- manage medication reminders
- log internal alerts for care-related events
- deliver an SPA frontend that aggregates these services

## Application stack

### Frontend
- **React** — UI framework for the single-page application
- **Vite** — build tool and development server
- **Tailwind CSS** — utility-first styling
- **nginx** — serves the production build of the frontend in Docker

### Backends
- **Node.js** — runtime for all backend services
- **Express** — HTTP server framework used by each service
- **PostgreSQL** — each service has its own dedicated database instance
- **Docker** — containerizes each service and each database
- **Docker Compose** — local orchestration for the full application stack

## Microservice architecture
ElderPinq consists of five main services:

1. **`ui-service`**
   - Stack: React + Vite + Tailwind + nginx
   - Port: `8080`
   - Purpose: provides the web interface for elder users and family members
   - Responsibilities:
     - displays login/register screens
     - shows dashboards for elders and family
     - communicates with backend APIs through `/api/*` endpoints

2. **`auth-service`**
   - Stack: Node.js + Express + PostgreSQL
   - Port: `3001` (mapped from container port `3000`)
   - Database: `users_db`
   - Purpose: handles authentication and user identity
   - Responsibilities:
     - user registration
     - user login
     - JWT token generation
     - authenticated user profile retrieval

3. **`health-service`**
   - Stack: Node.js + Express + PostgreSQL
   - Port: `3002`
   - Database: `health_db`
   - Purpose: stores and retrieves elder health data
   - Responsibilities:
     - record health check-ins
     - save vital signs like heart rate and blood pressure
     - return recent health metrics for a given user

4. **`reminder-service`**
   - Stack: Node.js + Express + PostgreSQL
   - Port: `3003`
   - Database: `reminder_db`
   - Purpose: manages medication reminders and adherence tracking
   - Responsibilities:
     - create medication reminders
     - list reminders for a user
     - mark reminders as taken

5. **`alert-service`**
   - Stack: Node.js + Express + PostgreSQL
   - Port: `3004`
   - Database: `alert_db`
   - Purpose: logs alerts and notifications generated by the system
   - Responsibilities:
     - receive alert events from internal workflows
     - persist alert records
     - provide recent alert history

## Data and service boundaries
Each backend service has its own isolated PostgreSQL instance with a separate database. This keeps service data separated and supports a microservice-style design, even though the services run together in the same Docker Compose environment.

### Database mapping
- `auth-service` → `users_db`
- `health-service` → `health_db`
- `reminder-service` → `reminder_db`
- `alert-service` → `alert_db`

## How the pieces fit together
- The frontend (`ui-service`) is the public entry point.
- It sends API requests to each backend service over the internal Docker network.
- Each backend service reads and writes only its own database.
- The `docker-compose.yaml` file controls service startup order and health-check dependencies.

## Why this design?
This architecture is useful for:
- demonstrating a microservices-style separation of concerns
- scaling services independently later
- deploying parts of the app separately to containers, Kubernetes, or ECS
- tracing and observing service-specific behavior

## Useful notes for deployment
- The application is Docker-native and ready for container-based deployment.
- The separate service databases make it easier to migrate to managed database services like Amazon RDS.
- The `/health` endpoints exposed by each backend are suitable for health checks in Kubernetes or load balancers.

## Summary
ElderPinq is a small yet complete demo of a microservices-enabled elderly care platform:
- one React-based UI service
- four Node.js backend services
- four PostgreSQL databases
- Docker Compose for local orchestration
- clean separation of authentication, health, reminders, and alerts
